# Founder Playbook

This document defines how I build products, write code, make decisions, and ship.
All agents and automations must follow this.

--------------------------------
PRODUCT PHILOSOPHY
--------------------------------
- Primary inputs:
  - Data
  - User conversations
- Speed > polish, but polish still matters.
- Prefer small, sharp tools.
- Open to evolving into larger all-in-one platforms only after traction.
- Avoid political products.

--------------------------------
TARGET USERS
--------------------------------
- Founders
- Indie hackers
- Developers
- Small businesses focused on growth
- I am industry-agnostic.

--------------------------------
MARKET STRATEGY
--------------------------------
- Prefer niche markets.
- Build many small products.
- Optimize for fast validation and fast iteration.

--------------------------------
TECH STACK
--------------------------------
- Next.js
- React
- Supabase backend
- Single repo per product or per business.
- No strong opinions on dependencies.

--------------------------------
ENGINEERING VALUES
--------------------------------
- Performance and readability are equally important.
- Highest performance possible with the least amount of code.
- Prefer simple solutions.
- Avoid unnecessary complexity.

--------------------------------
CODING STYLE
--------------------------------
- Tabs, not spaces.
- Favor readable code.
- Comments are encouraged, but not excessive.
- Comments should explain intent.
- Unsure about abstractions → default to simpler structure.

--------------------------------
UX PRINCIPLES
--------------------------------
- Balance power and simplicity.
- Prefer light mode, but support both.
- 4 clicks is too many.
- Errors should be friendly and blunt.

--------------------------------
MONETIZATION
--------------------------------
- Charge immediately.
- Free tier or free trial with limits.
- Subscriptions + optional lifetime one-time purchase.
- Target price: $10–$20 per month.

--------------------------------
LANDING PAGE BELIEF
--------------------------------
- Landing pages strongly affect adoption.
- Clear headline > fancy design.
- Fast load times.
- Obvious primary CTA.

--------------------------------
BUILDING IN PUBLIC
--------------------------------
- Post daily.
- Casual, authentic voice.
- Show wins and struggles.
- Primary platform: X (Twitter).

--------------------------------
PERSONAL OPERATING RULES
--------------------------------
- Build ~8 hours per day.
- Max 2–3 active projects.
- If nobody is using a product, investigate distribution before abandoning.
- Ship fast.
- Do not overthink.
- Launch many times.
- Keep trying until people start using it.
